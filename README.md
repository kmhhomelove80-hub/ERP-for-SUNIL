# 선일 통합 수주관리 · 3.0

## Windows 실행

1. ZIP **전체를 새 폴더에 압축 해제**합니다.
2. Python 3.12를 설치합니다. (3.13·3.14도 실행 지원)
3. 폴더의 **start.bat**을 실행합니다.
4. 설치가 끝나면 브라우저에서 프로그램이 열립니다.

서버가 실행되는 명령 창은 사용 중 열어 두세요. 종료는 Ctrl+C입니다.

## 5개 탭

- **업데이트**: 최초 엑셀 ZIP 등록, 이후 ERP·HMD·HHI·HSHI 전체 RAW 교체
- **수주현황**: 야드별 자료를 한 목록에서 검색·필터·엑셀 다운로드
- **추출**: POR 및 HSHI 블록 조건, 동일 행 수량 통합, 품목별 합계 병합, 엑셀 다운로드
- **REF 관리**: 거래처 분류와 SET 기준정보 조회·추가·수정
- **출고내역관리**: 추출 확정 내역 누적, 출고 상태·메모 관리, 엑셀 다운로드

### 최초 등록

업데이트 탭에서 기존 업무 엑셀 ZIP(XLSB/XLSX/XLSM도 가능)을 등록합니다.
ERP·REF와 야드 원본을 읽으며 기존 SET은 REF 관리의 SET 기준정보로 가져옵니다.
사용자 확인에 따라 진우엔지니어링주식회사와 세진기술산업(주)는 중소로 기본 등록합니다.
이전 버전의 classifications.sqlite3가 data 폴더에 있으면 최초 등록 시 분류를 가져옵니다.
다시 최초 등록을 실행하면 **전체 원본과 REF를 교체**하므로 확인창이 표시됩니다.

### 이후 업데이트

- 사내 ERP: 거래처부터 시작하는 전체 수주 원본을 업로드합니다.
- 야드: 기존 엑셀의 **빨간색 구분선 오른쪽 N열 이후 전체 RAW**를 머리글과 함께 업로드합니다.
- 해당 야드 전체 시트를 올린 경우에도 머리글로 구분해 읽을 수 있습니다.
- 선택한 대상만 전체 교체합니다. 다른 야드 RAW는 유지합니다.
- 머리글만 있는 파일은 해당 야드 자료를 비웁니다. 잘못된 파일은 저장하지 않습니다.
- ERP·REF 변경 시 모든 야드의 품목코드·수주정보·SET을 다시 계산합니다.
- 중소는 사내 ERP에서 자동으로 생성합니다.
- XLSX/XLSM/XLSB/ZIP, CSV·탭 구분 텍스트, 구형 바이너리 XLS(xlrd)를 지원합니다.
- HTML 형식의 XLS는 Excel에서 XLSX로 다시 저장해야 합니다.

### 기존 업무 규칙

- 중복 POR는 ERP·SET의 첫 번째 일치 행을 조회합니다.
- HMD: AP가 없으면 K=BI, L=Y. AP가 있으면 L=AP, K=AS(AS가 비었으면 BJ).
- HHI·HSHI의 수량·납기·납품처 매핑은 기존 VBA 기준을 유지합니다.
- 통합 수주현황에는 원본 행 전체를 보여줍니다. HMD 빈 납품처 제외는 **추출 단계에서만** 적용합니다.
- 추출에서 POR·호선·블록·품명·품목코드가 같으면 수량만 합산합니다.
- 날짜·납품처·금액 등이 달라도 첫 번째 행의 값을 유지하며 안내를 표시합니다.
- 품목코드별 합계는 화면(rowspan)과 엑셀에서 병합해 한 번만 표시합니다.
- POR 조건은 정확히 일치하는 값으로 조회합니다. 빈 조건은 대상 전체입니다.
- HSHI의 ‘POR, 블록’은 같은 줄이 AND, 줄 사이는 OR 조건입니다.
- SHI·ICOPS는 REF 관리의 야드 설정에서 원본과 ERP 매칭 열을 연결해 등록할 수 있습니다.

## 자료 저장과 버전 교체

모든 원본·REF·가공 결과는 **data/workspace.sqlite3**에 저장되어 재시작 후에도 유지됩니다.
새 버전은 새 폴더에 압축을 풀고 **기존 data 폴더를 복사한 후** 실행하세요.
서버를 종료한 상태에서 data 폴더를 별도로 백업하세요. GitHub ZIP에는 업무 자료가 들어 있지 않습니다.
현재 버전은 한 PC에서 사용하는 로컬 프로그램이며 인터넷 공개용 인증 서버는 아닙니다.
동시에 두 업데이트가 실행되면 나중에 저장하는 요청을 거부해 덮어쓰기를 막습니다.
파일당 25MB, 압축 해제 크기 100MB까지 지원합니다.

## 수동 실행

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

http://127.0.0.1:8000 에 접속합니다. 화면을 닫아도 서버를 종료하기 전까지 실행됩니다.

## 검증

```bash
python -m unittest discover -s tests -v
```

## 출고내역관리

추출 결과에서 **출고내역 확정**을 누르면 결과 전체를 출고 대기 상태로 누적합니다. 새로 등록한 묶음이 목록 맨 위에 나타나고, 같은 묶음 내부에서는 기존 품목 정렬을 유지합니다. 다운로드도 같은 순서입니다.
확정일시(한국 시간), 조선소, 확정 당시의 15개 열을 별도 원장에 저장합니다.
같은 확정 버튼을 다시 눌러도 같은 요청은 한 번만 등록됩니다.
다시 추출하여 새로 확정하는 것은 별도의 출고 묶음으로 누적되므로 실제 출고 건인지 확인하세요.

- 색상 없음: **출고 대기**
- 빨강: **재고 부족 · 출고 보류**
- 노랑: **출고 및 ERP 출고 완료**

체크박스로 여러 내역을 선택해 상태 또는 메모를 변경할 수 있습니다.
상태는 담당자가 지정하며 재고를 자동 판정하거나 사내 ERP에 출고를 전송하지 않습니다.
조회 필터는 조선소·상태·검색어·확정일 범위를 지원합니다.
업무 원본이나 REF를 변경해도 확정 당시 값은 유지됩니다.
최초 자료를 다시 등록하더라도 출고 원장은 유지되며, 백업은 기존처럼 서버 종료 후 data 폴더 전체를 복사합니다.
기존 출고리스트도 미리보기 후 색상을 유지해 가져올 수 있습니다.

수주현황의 선택·헤더 필터·연속 조회·화면 폭 개선 및 신규 야드 등록 기능은 3.0에 반영했습니다.

## 3.0 추가 기능

### 수주현황 행 선택·필터·연속 조회

조선소 앞의 체크박스로 행을 선택합니다. 첫 행 선택 후 Shift를 누르고 마지막 행을 클릭하면 필터·정렬된 목록에서 두 행 사이가 모두 선택됩니다.
화면 밖의 행도 범위에 포함되며, 필터 결과 전체 선택과 선택 해제를 지원합니다.
**선택 행 추출**은 POR를 다시 조회하지 않고 선택한 행 식별자만 전달합니다.
여러 야드를 함께 선택하면 야드별·품목코드별로 정렬하며 서로 다른 야드의 행은 합치지 않습니다.
원본이 변경된 후에는 이전 선택으로 추출할 수 없으며 최신 자료를 다시 조회해야 합니다.

각 헤더의 ▼에서 값 검색·복수 선택·빈칸 선택·오름차순/내림차순 정렬을 할 수 있습니다.
필터나 정렬 조건을 바꾸면 선택은 초기화됩니다. 조회 결과 다운로드는 현재 화면의 전체 필터·정렬 결과를 사용합니다.
페이지 버튼은 없으며 아래로 계속 스크롤합니다. 큰 목록은 필요한 화면 구간만 렌더링하지만 선택과 필터는 전체 논리 목록을 기준으로 작동합니다.
화면 좌우 폭을 넓히고 열 폭을 배분했습니다. 품명은 줄바꿈 없이 셀 폭에 맞춰 축소하며, 마우스를 올리면 원문을 확인할 수 있습니다.
작은 화면에서는 가독성을 위해 가로 스크롤이 생길 수 있습니다.

### 신규 야드 등록 (SHI·ICOPS 등)

1. REF 관리 → **야드 설정**에서 야드명과 머리글 행 번호를 지정합니다.
2. 샘플 RAW를 올리거나 최초 ZIP에 있는 같은 이름의 시트를 사용합니다.
3. **원본 열 불러오기**를 누르고 야드 매칭 열과 대조할 ERP 열을 연결합니다.
4. 호선·블록·품명·수량·납기·납품처의 원본 열을 선택합니다.
5. **매칭 미리보기**에서 일치·불일치·ERP 중복키 건수를 확인한 뒤 저장합니다.

여러 열 선택은 Ctrl을 사용하며 원본의 열 순서대로 문자열을 결합합니다. ERP 쪽도 선택한 열의 순서대로 결합합니다.
공백과 하이픈 제거 옵션을 제공하며, ERP 중복 매칭은 기존처럼 첫 번째 행을 사용합니다.
매칭 성공 시 POR·품목코드·수주정보는 일치한 ERP 행에서 가져옵니다.
등록된 야드는 업데이트·수주현황·추출 대상에 자동 추가됩니다. 이후 업로드도 등록한 샘플 열 구조를 따릅니다.
기존 HMD·HHI·HSHI의 특별 조건은 그대로 유지합니다. 신규 야드에 기존과 다른 복잡한 업무 조건이 필요하면 전용 규칙 추가가 필요합니다.
설정은 원본과 같은 DB에 저장되며 재시작 후에도 유지됩니다. 최초 자료 전체 초기화 시에는 신규 야드 설정도 초기화됩니다.

### 기존 출고리스트 가져오기

출고내역관리의 **기존 출고리스트 가져오기**에서 A~O 15개 열 XLSX를 올리고 미리보기 후 누적합니다.
빨강은 재고 부족, 노랑은 ERP 출고 완료, 색상 없는 행은 출고 대기로 가져옵니다.
합계 열의 병합 값은 내부 각 행에 보관하고, 표시·다운로드에서 같은 확정 묶음의 연속 구간을 병합합니다.
원본 H·K열에 별도 관리 번호가 있어도 값을 바꾸지 않습니다. 여러 야드가 섞인 과거 자료의 조선소 표시는 기본 ‘기존자료’입니다.
동일 파일은 내용 해시로 중복 가져오기를 막습니다. Excel에서 수정·재저장한 파일은 별도 파일로 취급하므로 중복 내역이 없는지 확인하세요.
과거 파일의 출고일이 없으면 가져온 시각을 확정일로 저장합니다.
