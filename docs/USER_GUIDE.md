# SUNIL 창고 관리 사용·인수인계 안내

이 문서는 구현된 기능의 사용법이다. 현재는 개발 환경 검증을 완료했으며 회사 운영 서버에는 배포하지 않았다. 운영 전 실제 파일 분류·담당자 검토·외부 접속 확인이 필요하다.

## 계정

관리자(staff)는 품목 등록, 입고/취소, 피킹/출고, 이동 처리, ERP 대조와 전체 이력을 관리한다. 일반 사용자는 재고 조회·위치별 할당 프로젝트 확인·본인 이동 요청/결과 조회를 사용한다. 후임자에게는 별도 계정을 발급하고 개인 계정을 공유하지 않는다. DEBUG=0 운영 로그인은 사용자명/접속주소 기준 10분 내 5회 실패 후 요청을 제한한다. 현재 단일 Gunicorn worker의 메모리 캐시를 사용하므로 여러 worker/서버로 늘리면 공유 캐시를 준비해야 한다.

## 매일의 업무

### 재고 조회

품번·모델·사양·위치로 검색한다. PC에서는 표, 휴대폰에서는 카드로 표시된다. 현재고는 도착분과 예정분을 포함한다. 가용량은 현재고에서 allocated를 뺀 값이다. 출하대기는 회사 ERP의 품목 전체 Sale Order 할당량이며 allocated와 다른 값이다. 여러 위치에 같은 출하대기 수량이 표시되더라도 위치별 수량으로 합산하거나 재고에서 다시 빼지 않는다.

### 입고와 예정 재고

새 물량은 입고 관리 → 새 입고 등록에서 품목·수량·위치·구분을 입력한다. 예정 물량은 예정일·담당자와 식별자를 따로 등록한다. 기존 예정 물량이 실제 도착했다면 재입고하지 말고 재고 목록의 ‘도착 확인’에서 실제 위치를 지정한다. 전량이 이동하고 예약도 함께 연결된다. 부분 도착은 현재 기능에 없으므로 별도 예정 건으로 나누어 등록하는 운영 규칙을 먼저 확인한다.

오입력 취소는 입고 원거래 목록에서 수행한다. 원거래 전량을 취소하며 사유를 남긴다. 가용량이 부족하거나 예정→도착 전환을 이미 했다면 차단한다. 원거래와 취소 이력은 삭제되지 않는다. 기존 Excel 보관 이력은 취소/재실행 대상이 아니다.

### 피킹과 출고

1. 프로젝트/호선과 고객사 자료에서 정리한 수량·ERP 코드 두 열(수량 먼저)을 헤더 없이 붙여넣는다.
2. 미리보기를 확인한다. 중복 품번은 합산하고 현재 원장 순서로 배정한다. FIFO/최단 동선 최적화는 아니다.
3. 부족표의 Y02는 등록된 본사 ERP 자료의 참고 수량이다. 자료 없음은 0으로 확정한 값이 아니다. Y02 재고를 부산에서 자동 예약하지 않는다.
4. 부족이 있으면 확보 가능한 물량만 예약한다는 동의 후 등록한다. 미리보기 자체는 예약이 아니며 30분 후 만료된다. 재고가 바뀌면 다시 계산한다.
5. 피킹리스트에서 인쇄/PDF 저장을 사용한다. 저장 후 파일이 열리고 품번/수량/위치/페이지가 맞는지 확인한다.
6. 예정분이 도착하면 위치를 확정하고 실제 물건을 출고한다.
7. 일반 배정은 예약/출고에서 실제 출고 완료한 행만 선택하고 실제 출고 시각을 입력해 Release한다. 각 행 전량을 처리하고 미선택 예약은 남는다. 예약을 그만두는 경우에는 Release가 아니라 예약 취소를 선택한다.

### 모바일 이동

재고 카드에서 이동 요청을 등록한다. 요청 등록만으로 전산 재고는 바뀌지 않는다. 관리자는 재고 이동 목록에서 요청을 열고 반영 또는 사유를 입력한 거부를 수행한다. 처리 시점에 잔량을 다시 검사하므로 요청 당시 가능했어도 이후 예약으로 거부될 수 있다. 완료/거부 결과는 본인 목록에서 확인한다. 물리적 이동을 요청 전/후 어느 시점에 하는지는 현장 인수인계 시 통일해야 한다.

### 회사 ERP 대조

표준 양식을 다운로드해 ‘ERP재고’ 시트의 창고(Y09/Y02), ERP 코드, 현재고, 출하대기, 모델명을 입력한다. 기존 SUNIL 파일의 재고현황 시트도 사용할 수 있으나 I:R=Y02, W:AF=Y09 배치를 확인해야 한다.

회사 ERP 자료 기준 시각은 자료의 기준일이며, 관리 재고는 등록 확정 시점의 값을 보관한다. 과거 시각을 입력해도 과거의 창고 재고를 자동 재구성하지 않는다. 차이는 ‘도착 완료+예정−ERP 현재고’다. ERP에 없는 품번은 누락으로 표시하고 0으로 임의 처리하지 않는다. 회사 ERP의 음수는 원본 그대로 보존해 확인 대상으로 표시한다.

차이 항목의 미검토 링크에서 원인·조치를 기록한다. ‘조치 완료’는 해당 차이에 대한 업무 확인 상태이며 과거 수량을 0 차이로 덮어쓰지 않는다. 실제 재고/ERP를 수정한 뒤 새 자료로 다시 대조해 수량 일치를 확인한다.

### 이력과 과거 보관

작업 이력은 새 시스템 거래를 검색한다. 기존 Excel 이력 보관은 과거 BACKUP/작업로그/AppSheet 원본 행을 읽기 전용으로 검색한다. 과거 기록을 가져와도 현재 재고를 다시 가산·차감하지 않는다. AS 자료는 이관하지 않는다.

## 퇴사 전 인수 확인

- 후임자 별도 계정으로 로그인하고 PC/실제 휴대폰에서 업무 한 사이클을 수행한다.
- 회사 ERP와 관리 수량 차이 목록의 원인/조치 상태를 설명한다.
- ‘9/10 입고’ 등 현재 상태가 확정되지 않은 임시 위치와 미입고 물량을 확인한다.
- 회사 소유 서버/도메인/결제/복구 계정의 보유자를 정한다.
- 완료된 백업의 회사 저장공간 보관 위치와 새 DB 복원 절차를 후임자가 직접 확인한다.
- 운영에 쓸 최종 데이터 전환 시점과 기존 Excel 중단 시점을 정한다. 검증 중에는 두 시스템에 같은 거래를 중복 입력하지 않도록 시험 데이터와 운영 데이터를 구분한다.

서버 운영/복구 절차는 deploy/README.md를 참고한다. 이 문서에는 암호·토큰을 기록하지 않는다.

## 회사 장비 운영 준비

Synology DS1621+를 NAS 백업 대상으로, 상시 가동 Windows Server를 실행 후보로 준비 중이다. Windows 실행/예약 작업은 deploy/windows/README.md를 참고한다. NAS의 DSM 관리 주소(5001)와 ERP 업무 주소는 별도로 설정한다. 실제 장비 연결과 외부 접속은 아직 구성하지 않았다.

관리자는 ‘운영 점검’에서 DB 구조·원장 allocated/활성 예약 합계·예정일 확인 대상을 볼 수 있다. 불일치가 나오면 원본/최근 거래를 확인하고 개발 담당자에게 전달한다. 점검 화면은 수량을 자동 보정하지 않는다.

## 완료 거래 재조회와 엑셀 검토

예약/출고 화면의 ‘피킹 주문 이력’에서 진행 중/출고 처리 완료/전체 취소 주문을 검색한다. ‘전체 행별 거래’는 기존 SEQ까지 포함해 검색한다. 예약 중인 위치는 현재 연결된 실제 위치를 표시하고, 출고/취소가 끝난 거래는 처리 당시 품번·모델·사양·위치를 고정해 보여준다. 처리 이후 품목 설명을 수정해도 완료 기록은 바뀌지 않는다. 당시 상세 정보가 없던 이전 거래는 현재 정보라는 안내가 표시되며 과거 값을 임의로 복원하지 않는다.

재고 조회와 ERP 대조의 ‘현재 조건 전체 엑셀 내보내기’는 해당 검색 조건의 전체 행(최대 50,000행)을 출력한다. 화면의 한 페이지만 내보내는 것이 아니다. 회사 ERP 원본 음수·누락은 보존하고, 문자열을 수식으로 실행하지 않는다. 내보낸 파일은 조회/검토용이며 원본 파일 및 DB 백업을 대체하지 않는다.

실제 담당자가 수행하고 결과를 남길 항목은 [운영 전환·후임자 인수 검증표](HANDOVER_CHECKLIST.md)를 사용한다. 현장 미실행 항목과 개발 환경 통과 항목을 구분한다.

## 2026-10-31 개선 기능

### 검색과 일괄 입고

재고 검색은 ERP 코드·모델·사양·위치를 입력하고 약 0.3초 멈추면 목록과 합계가 갱신된다. 한글 조합이 끝난 뒤 조회하며, 입력창의 커서는 유지한다. 검색 버튼도 사용할 수 있다. 현재 검색 전체 엑셀 링크 역시 같은 조건으로 바뀐다.

입고 관리 → **엑셀 일괄 입고**에서 A~E열(품목코드·품목명·사양·수량·Location)을 복사하거나 XLSX/XLSM을 선택한다. 처음의 입고 LIST 제목/헤더는 건너뛰고 최대 1,000행을 검토한 뒤 확정한다. 모든 행이 입고 완료로 처리되므로, 이미 등록한 예정 재고의 도착 확인과 중복으로 사용하지 않는다. 신규 품목은 생성하고 기존 품목 설명은 유지한다. 동일 품목이 여러 행이어도 원본 행마다 입고 거래를 남긴다. 한 행이라도 수량/위치/누적 재고가 잘못되면 전체를 반영하지 않는다. 같은 확정 요청 재전송은 중복 입고하지 않는다.

### 피킹 입력 순서와 고객 양식

일반 두 열 입력은 **수량 → ERP 코드** 순서다. 예를 들어 `4<TAB>CODE001`을 붙여넣는다. 헤더 없이 최대 500행이며 동일 코드는 합산한다. 숫자로 된 ERP 코드도 문자열로 보존한다. 이전 ‘코드→수량’ 순서는 자동 추측하지 않으므로 순서를 바꿔 입력한다.

고객 양식은 두 열 입력 대신 **POR번호·호선·블록·품명·수량·ERP CODE** 6열을 붙여넣거나 XLSX/XLSM으로 입력한다. 고객 자료는 주문에 함께 저장된다. 등록 후 기본 위치별 피킹리스트와 **고객 양식 인쇄** 중 선택할 수 있다. 고객 양식은 원본 고객 행 순서를 유지하고 연속된 동일 ERP 코드 묶음에 합계/Location별 수량을 병합 표시한다. 같은 코드가 나중에 다시 나오면 이전에 표시한 배정을 재사용하지 않고 남은 배정만 표시한다.

고객 양식은 A4 세로이며 여러 Location은 줄바꿈한다. 현재 시스템의 부족 수량은 빨간 글씨로 명시한다. 원본 Excel 셀의 빨간 배경을 업무 상태로 사용하지 않는다. 예정 재고 포함 여부도 표시한다. 출력은 저장된 예약을 읽기만 하며 재예약하지 않는다. 취소한 예약은 위치 배정에서 제외하고 남는 요구량을 부족으로 표시한다. 과거 이관/고객 자료 없이 만든 기존 주문에는 고객 정보가 없으므로 기본 양식을 사용한다.

### 프로젝트 단위 출고

예약/선택 출고에서 프로젝트와 SEQ(신규 주문은 주문 ID)로 범위를 좁힌다. 현재 페이지 전체 선택 및 **Shift+클릭 범위 선택/해제**를 사용할 수 있다. 범위 선택은 현재 페이지 기준이며 페이지 이동 시 개별 체크는 유지하지 않는다.

프로젝트 전체를 처리하려면 **필터 결과 전체 N행 처리**를 선택한다. 다른 페이지까지 포함하고 대상 행 수를 표시한다. 처음 조회한 뒤 대상이 늘거나 줄면 새로 조회하도록 차단한다. 각 행은 전량 처리하며, 예정 재고가 섞여 실제 도착 확인이 안 됐다면 전체 Release를 차단한다. ‘전체 처리’는 실제로 출고한 프로젝트에만 사용한다.

### 회사 ERP 직접 추출 파일

ERP 자료 등록의 **ERP 직접 추출 y09.xls / y02.xls**를 선택한다. 부산 파일은 Y09 칸, 영주 파일은 Y02 칸에 넣고 회사 ERP 자료 기준 시각을 확인한다. 두 파일 동시 등록 또는 창고 하나만 등록할 수 있다. 하나만 올리면 해당 창고만 새 자료로 갱신하고 다른 창고 참고 자료는 이전 최신 자료를 유지한다.

제공된 파일은 CP949 한글 탭 구분 자료에 XLS 확장자가 붙은 형식이다. 품목코드·품목명·현재고·출하대기 헤더를 확인해 읽으며 마지막 합계 행을 제외한다. 음수와 0을 보존하고 소수 수량/수식/중복 코드는 오류로 알린다. 직접 추출 자료의 Location Number는 로케이션 원장을 덮어쓰는 데 사용하지 않는다. 실제 바이너리 XLS 형식은 XLSX로 저장해야 한다. 기존 표준 ERP재고 및 SUNIL 재고현황 형식도 계속 사용할 수 있다. 비교/차이 원인·조치 이력은 그대로 보존한다.

고객 양식의 ERP CODE는 화면과 A4 PDF에서 줄바꿈 없이 한 줄로 표시하며, 셀보다 긴 경우 전체 코드가 들어가도록 글자를 자동 축소한다.

## 대체 출고: 빌림 → 입고분으로 상환

코드가 다르지만 동일한 제품이거나 필요한 수정으로 동일해지는 제품을 사용자가 확인해 **1:1 수량으로** 처리한다. 코드가 비슷하다는 이유로 시스템이 자동 대체하지 않는다. 고객은 대체품을 계속 사용하고, 나중에 생산 입고분으로 빌린 재고를 보충하는 흐름이다.

1. 기존처럼 피킹을 등록한다. 부족한 물량을 확인하고 주문 상세의 **대체품 배정**에서 요청 코드·빌릴 제품/위치·수량·사유를 입력한다. 정상/대체 배정 합계는 고객 요청량을 초과할 수 없다. 이 단계는 예약이다. 요청 코드 재고가 전혀 없으면 부족 확인 후 **전량 부족 · 대체 배정용 주문 만들기**로 주문을 먼저 만든다.
2. 동일 제품 또는 필요한 수정 완료와 실제 출고를 확인한 뒤 **대체 출고(빌림)**를 처리한다. 빌린 코드의 현재고/예약을 줄이고 미상환으로 남긴다. 일반 Release로 확정하지 않는다. 일반 예약/출고 화면에는 대체 배정을 제외하므로 정상 배정만 따로 처리한다.
3. 생산 완료 물량은 **요청 코드로 실제 입고** 등록한다. 기존 예정 물량이면 재입고하지 않고 도착 확인한다.
4. 빌림 상세에서 해당 입고 건·상환 수량·제품 수정 내용/근거를 입력하고 **입고분으로 상환**한다. 요청 코드 재고를 줄이는 만큼 빌린 코드 재고를 **생산품의 실제 입고 위치**에 늘린다. 추가 입고/고객 재출고가 아니며 전체 실물 수량은 그대로다. 5개를 3개+2개처럼 부분 상환할 수 있다.
5. 전량 상환 후 회사 ERP의 코드·수량을 확인하고 **회사 ERP 정산 확인**을 남긴다. 확인/확인 취소는 메모와 이력만 남기며 수량을 바꾸지 않는다. 차이 원인 검토 상태나 과거 비교 수량을 자동으로 변경하지 않는다.

예: A 10개 요청, A 5개 정상 출고+B 5개 빌림 → 창고 A/B 모두 0. 이후 A 5개 실제 입고 → A 5/B 0. 상환 → A 0/B 5, 위치는 새 입고 위치. 회사 ERP A 0/B 5와 다시 대조한다.

**추적과 차단**

- 주문 상세와 고객 양식에서 요청 코드와 실제 대체 코드를 함께 확인한다. 고객 양식은 저장된 배정을 읽으며 다시 예약하지 않는다. 상환 후에도 당시 출고 위치는 유지한다.
- ERP 차이 행의 **대체 출고 연결**에서 같은 기록을 연다. 비교 후 등록한 빌림은 제외하고, 상환 수량은 ERP 기준/비교 시각 중 이른 시각까지 계산한다. 현재 상세의 상환/확인 상태와 과거 기준 수량은 구분한다. ERP 엑셀 출력에도 관련 건수/기준시각 미상환 수량을 덧붙인다.
- 빌림 출고 전에는 예약 취소가 가능하고 기록은 남긴다. 이미 고객에게 나간 대체품을 일반 취소로 재고 복구하지 않는다. 실제 반품/오출고의 역거래는 이 기능에 포함하지 않는다.
- 상환은 빌림 이후 실제 입고된 요청 코드의 유효한 입고 건을 사용한다. 예정 선등록 후 실제 도착이 빌림 이후라면 도착 연결된 입고 건도 사용할 수 있다. 입고 건 미사용량과 현재 가용량을 모두 검사한다.
- 같은 확정 요청의 재전송/동시 상환으로 재고가 중복 증가하지 않는다. 상환에 사용한 입고 원거래는 일반 취소를 막는다. 기록의 삭제/직접 편집은 제공하지 않는다. 잘못 확정한 상환을 되돌리는 별도 역거래는 현재 제공하지 않으므로 확정 전 코드·수량·위치를 확인한다.
- 원본 Excel의 빨간 바탕/노란 글씨는 AS·이동·맞교환 등이 섞여 있어 **자동으로 빌림 기록으로 변환하지 않았다**. 기존 메모/SEQ는 조회할 수 있지만 새 구조의 대체 기록과 같다고 간주하지 않는다. 본 기능은 새 피킹 주문의 명시적 대체 배정부터 적용한다. 과거 미상환의 초기 연결은 담당자 검토가 필요하다.


## 피킹 인쇄 크기 설정

기본/고객 양식 상단의 **인쇄 설정**에서 표 글자 크기 7~12pt와 행 간격(좁게/보통)을 선택한다. 기본값은 **8pt·좁게**다. 사용자가 기존 10pt 양식을 80%로 출력했을 때 적당하다고 확인한 크기를 기준으로 정했다. 화면 표에도 즉시 반영하며 같은 브라우저에서는 두 양식에 공통으로 유지된다. ‘기본값으로’는 8pt·좁게로 초기화한다. 다른 기기/브라우저에는 별도로 설정한다.

새 기본값 사용 시 브라우저 인쇄 배율은 **100%**로 놓는다. 여기에 80%를 다시 적용하면 글자가 더 작아진다. 브라우저의 실제 인쇄 배율은 프로그램이 강제 설정하지 않는다. ERP CODE는 선택한 크기보다 길면 셀 안에 들어가도록 추가 축소하며 자르거나 줄바꿈하지 않는다. 제목은 12pt로 정리하고 안내/설정 패널은 인쇄에서 제외한다. 실제 페이지 수는 품명/위치 수와 인쇄 설정에 따라 달라지므로 미리보기를 확인한다.


## 피킹 총수량 확인

배정 미리보기와 등록된 기본/고객 피킹리스트에 **요청 총수량·피킹 배정 총수량·미배정 수량**을 표시한다. 요청 코드별 수량까지 맞으면 ‘요청 수량과 일치’로 표시한다. 여러 위치에 나뉜 배정은 수량을 합산하고 취소된 행은 제외한다. 대체품은 요청 코드에 연결해 한 번만 합산하며 정상/대체 배정 수량도 나눠 보여준다. 빌림 상환 기록을 별도 피킹 물량으로 다시 더하지 않는다. 이 합계는 인쇄/PDF에도 표시한다.

피킹 배정 합계는 현재 유효한 배정(예약·일반 출고·대체 출고/상환 완료)을 뜻하며, 실제 출고 완료 수량만의 합계와는 다르다. 원래 요청 자료가 없는 이전 기록은 요청 수량을 0으로 추정하지 않고 ‘미기록’으로 표시한다.


## 휴대폰 사용 범위

휴대폰은 **재고 조회·할당 프로젝트 확인·재고 이동 요청/결과 확인**으로 간소화한다. 재고 카드의 예약 수량 ‘N개 할당 내역’을 누르면 해당 위치에 현재 할당된 프로젝트/호선·SEQ/주문·수량을 확인한다. 신규 주문은 등록자/등록 시각도 표시하고, 기존 Excel 자료는 원본 프로젝트/SEQ를 그대로 보여준다. 대체 예약은 고객 요청 코드도 구분한다. 완료 출고/취소/이미 나간 빌림은 현재 allocated에서 제외한다. 전체 합계는 다른 페이지까지 포함하며 원장 불일치가 있으면 수정하지 않고 관리자 확인을 안내한다.

모바일 화면에는 입고/도착 확인·피킹 등록·Release·ERP 대조·운영 점검·엑셀 내보내기·이동 승인 버튼을 표시하지 않는다. 이동은 기존대로 휴대폰 요청 후 PC에서 반영/거부한다. 관리자 계정으로 휴대폰을 열어도 화면 메뉴는 간소화하지만, 이는 화면 구성이고 계정 권한 자체를 바꾸지는 않는다. 권한도 제한하려면 휴대폰용 일반 계정을 사용한다. 일반 계정은 PC 관리 URL에도 접근할 수 없다.


### 휴대폰 화면 최적화

휴대폰에서는 상단에 로고/로그아웃, 하단에 **재고 조회·재고 이동** 고정 메뉴를 표시한다. 현재 메뉴는 강조된다. 검색창은 화면 전체 폭을 사용하고 스크롤 중에도 찾기 쉽게 유지한다. 재고 수량은 카드로 표시하며 allocated를 누르면 프로젝트별 내역으로 이동한다.

작은 화면에서도 긴 코드/프로젝트가 페이지 밖으로 밀리지 않도록 줄바꿈하고, 카드·입력칸·주요 버튼은 터치하기 쉽게 배치했다. 이동 수량 입력은 숫자 키패드를 유도하고 확인 체크박스는 왼쪽에 둔다. 하단 메뉴가 마지막 입력/버튼을 덮지 않도록 여백을 확보하고 휴대폰 안전 영역을 반영한다. 화면 확대를 강제로 막지 않는다. 실제 키보드·주소창 동작은 휴대폰/브라우저에 따라 다를 수 있다.
