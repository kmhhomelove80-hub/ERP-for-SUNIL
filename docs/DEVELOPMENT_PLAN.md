# 개발계획 및 진도 관리

## 목표와 마감

2026-11-30 퇴사 전 전환·인수인계가 목표다. 필수 기능 구현 목표는 11/20, 실제 대조/수정은 11/21~25, 최종 전환·인수인계는 11/26~30으로 잡았다. 현재 개발 환경 구현이 앞서 진행됐으므로 남은 기간은 실제 운영 환경과 후임자 검증에 우선 배정한다. 채팅 밖에서 자동 작업이 계속되지는 않는다.

전체 범위 최초 예상은 100~150 인시, 압축 필수 범위 예상은 60~90 인시였다. 이는 사람의 개발·검토 작업량 참고치이며 실제 에이전트 경과시간과 같지 않다. 완료 단계 수는 작업량 가중 진척률이 아니다.

## 확정 업무 규칙

- 부산 Y09 위치별 재고 관리, 영주 Y02는 본사 참고 수량. 회사 ERP를 보완하며 AS는 제외한다.
- 입고 예정 재고도 피킹 가능. 도착 확인 시 총량을 다시 더하지 않고 위치/예약을 전환한다.
- allocated는 피킹 예약, 출하대기는 회사 ERP Sale Order 총 할당량. 이중 차감하지 않는다.
- 일반 배정은 실제 출고 후 선택 행의 전량을 Release한다. 대체 배정은 일반 Release 대신 빌림 출고 후 요청 코드 생산 입고분을 빌린 코드로 전환해 상환한다. 미선택 예약은 남기며 행 안의 일부 수량만 Release하는 기능은 넣지 않는다.
- 피킹은 ERP 코드·수량 붙여넣기, 원장 순서 배정. ERP 직접 API 연계/FIFO/동선 최적화는 초기 범위 밖이다.
- 모바일 요청은 관리자 확인 후 반영한다. 물리적 이동의 세부 시점은 현장 운영 규칙으로 인수 확인한다.
- 회사 ERP 비교는 기준 시각과 등록 시각을 구분하고 원본 음수/누락을 숨기지 않는다. 비교/과거 이력 이관이 실제 재고를 덮어쓰지 않는다.

## 남은 진행 조건과 순서

1. 상시 가동 Windows Server의 버전/RAM/디스크·실행 계정 권한과 Synology DS1621+의 DSM/RAM/SMB 공유를 확인한다. Windows+NAS 백업을 기본안으로 준비하며 NAS 컨테이너 통합은 설치 가능 여부/부하 확인 후 결정한다. 기존 클라우드 가격 조회는 선택 사항이며 이 경로를 막지 않는다.
2. ERP 전용 접속 호스트명/HTTPS 경로와 NAS 백업 공유 권한을 준비한다. DSM 관리 화면 5001과 ERP 접속을 구분한다. 공개 배포·환경 게시·원격 push는 별도 승인 없이 하지 않는다.
3. 후임자 확정 후 USER_GUIDE.md 흐름으로 인수 검증. ‘9/10 입고’ 상태와 원본 기준 차이 12항목의 업무 확인.
4. 실제 호스트의 HTTPS·DB·백업 timer·회사 저장공간 복사·새 DB 복원을 검증.
5. 최종 데이터 기준 시점을 잡고 전환한다. 기능 추가보다 검증/인수와 장애 복구에 남은 기간을 사용한다.

새 요구사항이나 실제 검증에서 범위가 바뀌면 완료 기준과 예상 작업량을 갱신한다. 테스트 통과/미실행/skip/운영 미확인을 구분해 기록한다. 암호나 토큰을 문서에 저장하지 않는다.
