# Windows 노트북 기능 테스트

회사 서버 설치 없이 노트북 하나로 시험하는 버전이다. 실제 Excel·OneDrive·NAS·회사 ERP에 연결하지 않는다. 시험 중 변경은 압축을 푼 폴더의 `laptop-data/trial.sqlite3`에만 저장된다. 운영 배포용 설정과 구분한다.

## 처음 실행

1. Python 공식 사이트 https://www.python.org/downloads/ 에서 **Python 3.12의 Windows 설치 프로그램**을 설치한다. 설치 옵션의 Python Launcher(`py`)를 포함한다. 이미 있으면 명령 프롬프트에서 `py -3.12 --version`으로 확인한다.
2. 받은 ZIP을 **모두 압축 해제**한다. 예: `C:\SUNIL-ERP-TEST`. OneDrive 동기화 폴더는 피한다. ZIP 안에서 직접 실행하지 않는다.
3. 폴더의 **LAPTOP-START.cmd**를 더블클릭한다. 최초 실행에는 인터넷으로 Python 패키지를 설치하므로 몇 분 걸릴 수 있다. 관리자 권한 실행은 필요하지 않다.
4. 계정 생성 안내가 나오면 사용자명과 이메일(선택), 암호를 입력한다. 암호는 입력 중 화면에 표시되지 않는 것이 정상이다. 10자 이상의 암호를 사용한다. 이 계정은 노트북 시험 전용이다.
5. 브라우저에 접속 오류가 먼저 보이면 콘솔에 서버 시작 안내가 나온 뒤 새로고침한다. 주소는 `http://127.0.0.1:8000/`이다. 방금 만든 계정으로 로그인한다.

다음 실행부터도 같은 파일을 더블클릭한다. 데이터와 계정은 유지하고 가상 데이터는 중복 등록하지 않는다. 실행 중 검은 창을 열어 두고, 종료할 때는 창에서 Ctrl+C를 누른다. 노트북을 종료하면 다른 곳에서 접속할 수 없다. 휴대폰/외부 인터넷 접속은 이 로컬 시험 패키지에 포함하지 않는다.

## 권장 시험 순서 (약 30~60분)

초기 가상 재고는 DEMO-001 30개(A0101 20/B0101 10), DEMO-002 예정 10개, DEMO-003 5개로 총 45개다. 실제 회사 품목이 아니다.

1. 재고 검색에서 `DEMO-001`, `A0101`을 각각 검색한다.
2. 새 피킹에 호선 `시험호선`을 입력하고 아래 두 열을 붙여넣는다. 코드와 수량 사이에는 탭 또는 공백을 사용한다.

   ```text
   DEMO-001 4
   DEMO-002 3
   ```

3. 미리보기와 예약을 확인한다. 예정 재고 DEMO-002도 배정된다. 피킹리스트를 인쇄하거나 PDF로 저장한다.
4. 재고 조회에서 DEMO-002의 ‘도착 확인’으로 실제 위치 `D0101`을 지정한다. 총수량은 그대로이고 위치가 바뀌는지 확인한다.
5. 실제 출고를 가정해 예약/출고에서 한 행을 선택하고 과거 또는 현재의 출고 시각으로 Release한다. 선택 행 전량만 줄어드는지 확인하고, 남은 행은 예약 취소를 시험한다.
6. DEMO-003의 가용 수량 1개를 다른 위치로 이동 요청한다. 관리자 처리 전후 수량과 처리 결과를 확인한다.
7. 입고 등록/원거래 취소, 완료 피킹 이력, 작업 이력, 현재 검색 조건 엑셀 다운로드를 시험한다.
8. 회사 ERP 대조에서 표준 양식을 다운로드하고 가상 코드의 Y09/Y02 수량을 넣어 업로드한다. 일부러 수량을 다르게 넣고 원인·조치를 기록해 본다. 실제 재고가 비교 자료로 덮어써지지 않는지 확인한다.

일반 모바일 사용자 권한은 `/admin/` → 사용자에서 별도 사용자를 추가하고 staff/슈퍼유저를 해제한 뒤 다른 브라우저의 비공개 창으로 시험할 수 있다. 작은 화면은 브라우저 폭을 줄여 확인한다. 실제 휴대폰 기기 검증은 회사 접속 환경 구성 후 진행한다.

기존 Excel 이관·과거 보관은 빈 DB 조건이 있으므로 가상 데이터와 섞지 않는다. 실제 파일로 시험하려면 이 패키지의 첫 기능 시험을 마친 뒤 별도 시험 폴더에서 진행한다. 원본을 덮어쓰지 않는다.

## 실행 문제가 있으면

- `py`를 찾지 못함: Python 3.12와 Python Launcher 설치를 확인하고 창을 다시 연다.
- 패키지 다운로드 실패: 인터넷/회사 프록시 연결과 오류 문구를 확인한다. TLS 검증을 끄지 않는다.
- 계정 생성 도중 종료: 다시 실행하면 계정 생성을 재시도한다.
- 8000 포트 사용 중: 앞서 실행한 시험 창을 닫고 다시 시작한다. 회사 프로그램을 임의로 종료하지 않는다.
- 암호 재설정: 압축을 푼 폴더에서 명령 프롬프트를 열고 `py -3.12 scripts\laptop.py manage changepassword 사용자명`을 실행한다.
- 처음부터 재시험: 실행 창을 종료한 뒤 **laptop-data 폴더를 다른 이름으로 바꾸고** 다시 시작한다. 기존 시험 데이터는 별도 보존하고 새 계정을 만든다.

오류가 나면 계정 암호를 제외한 오류 문구/화면을 전달한다. 현재 Windows 실행 파일은 준비됐지만 개발 환경은 Linux이므로 실제 Windows에서 최초 실행 결과 확인이 필요하다.
