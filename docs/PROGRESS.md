## 배치 007 — 거래 이력 보존·완료 주문 검색·엑셀 출력

실행 기록: 한국 시간 2026-10-31 01:49~02:04, 약 15분 경과. 장비 정보 없이 진행 가능한 업무/데이터 보존 검토와 검증을 수행했다. 최초 예상 인시와 에이전트 경과시간을 구분한다.

### 발견 문제와 수정

- 처리 완료된 피킹 상세가 품목 마스터 수정 영향을 받을 수 있는 경로를 확인해, 배정 당시 및 출고/취소 당시 상세를 별도 보존했다. 완료 후 품번·모델·사양·위치·상태는 처리 당시 기록을 표시한다.
- 예정 배정은 실제 도착 위치로 계속 연결하면서 최초 배정 위치도 유지한다. 새 도착/이동 위치에는 기존 원장 설명을 이어받는다.
- 이전에 종료 상세가 저장되지 않은 거래는 현재 정보라는 안내를 표시하고 과거 값을 추정해 채우지 않는다.
- 완료 주문도 찾아 인쇄하는 피킹 목록과 기존 SEQ 포함 전체 행별 거래 검색을 추가했다. 처리 시각/담당자를 표시하고 취소도 시각을 보존한다.
- 일반 모바일 사용자의 PC 피킹 상세/이력 권한을 관리자 정책에 맞춰 제한했다. 사용 중인 ERP 코드는 관리자 편집에서 고정한다.
- 입고 수량의 소수/불리언/범위 초과 및 합산 범위를 검증하고, 이동 도착 수량 한계 초과 시 출발 수량을 바꾸지 않고 거부한다.
- 재고/ERP 대조 검색 전체 엑셀 출력(최대 50,000행), 문자열 수식 실행 방지, 원본 음수/누락 보존, 과다 행의 명확한 오류 응답을 구현했다.
- Windows 읽기 전용 사양 확인 스크립트와 상시 작업의 기본 시간 제한 해제 등 인수 문서를 보완했다. 실제 Windows 실행은 아직 미검증이다.

### 검증 결과

- SQLite: 85개 발견, **82개 통과 / PG 전용 3개 skip**.
- PostgreSQL: 85개 발견, **83개 통과 / SQLite 파일 전용 2개 skip**. NAS 모사 저장소 복사/새 PG DB 복원 대조 통과.
- 회귀 범위: 완료 상세의 마스터 수정 독립성, 취소 상세/기존 SEQ 검색, 예정→도착 연결, 감사 실패 시 전체 원복, 검색 시 주문 행 수 정확성, 권한, 입고/이동 정수 범위, Excel 수식 문자열/누락/음수/행 수 제한.
- 초기 주문 행 수 테스트에서 템플릿 렌더 후 Page.object_list가 list인 점을 잘못 다룬 테스트 오류를 수정했고 최종 회귀가 통과했다.
- 실제 Waitress/Chromium: 기존 전체 업무 흐름 + 선택 출고→완료 주문 찾기→관리자 품목 수정→이전 피킹 상세 유지, 행별 이력, 실제 xlsx 다운로드까지 통과했다. 현재고 17과 과거 ERP 비교 차이 2가 각각 유지되는 것을 확인했다. 가상 데이터만 사용했다.
- 산출물: validation/browser-history/의 화면, 완료 피킹 PDF, 재고/ERP xlsx, result.json. 화면도 직접 확인했다.
- 새 스키마로 실제 원본 전체 격리 이관/행별 원문/ERP 대조/SQLite 복원 검증을 다시 수행해 현재고 25,754/예약 5,460 및 기존 모든 건수가 유지됨을 확인했다. 원본 두 파일 해시 불변.

### 현재 진행 조건

**단계 수 기준 5/7, 약 71%를 유지한다.** 핵심 기능의 검증은 보강됐지만 M6/M7의 실제 회사 장비 적용·인수 검증은 끝나지 않았다.

다음 적용에는 실제 Windows 버전/RAM/디스크와 실행 계정 권한, NAS DSM/RAM/공유 경로/SMB 권한이 필요하다. 모델만으로 메모리 여유나 Container Manager 설치를 확정하지 않는다. Inspect-Server.ps1은 이 정보 중 비밀값 없는 Windows 사양만 읽도록 준비했다. 확인 전 실제 장비 설치·재부팅·인증서·백업 작업을 실행하지 않는다.

서버 구매·공개 배포·환경 게시·NAS 관리 화면 접속·원격 push는 하지 않았다. 11/20 기능 구현, 11/30 전환·인수인계 목표는 유지한다.

## 배치 006 — Windows 서버·Synology NAS 운영 준비

실행 기록: 한국 시간 2026-10-31 01:33~01:46, 약 13분 경과. 사용자가 상시 가동 Windows Server와 NAS 정보를 제공해 운영 준비 방향을 반영했다. 경과시간은 최초 예상 인시와 다르다.

### 장비와 진행률

NAS는 Synology DS1621+, 가용 약 10.5TB로 확인했다. Windows Server 버전/RAM 및 NAS DSM/RAM/Container Manager 상태는 미확인이다. Windows 실행 + NAS 백업을 기본안으로 준비하고 NAS 컨테이너 운영도 검토 가능한 선택지로 남겼다. 외부 관리 주소에 접속하거나 인증정보를 요청하지 않았다.

**전체 완료는 5/7단계, 단계 수 기준 약 71%를 유지한다.** M6 준비가 진행됐지만 실제 Windows 기동/SMB/재부팅/HTTPS 검증 전에는 단계 완료로 올리지 않는다. 이 수치는 작업량 가중률이나 운영 준비율이 아니다.

### 구현

- Windows 지원 WSGI 서버 Waitress 3.0.2 추가, Gunicorn 의존성의 Windows 제외, Windows 시간대 의존성과 CI 작업 준비.
- Windows PostgreSQL pg_dump/pg_restore의 .exe 경로 처리.
- Windows 비밀값 없는 runtime 예제, 현재 계정/컴퓨터 DPAPI 비밀 파일 준비, 앱/HTTPS/백업 PowerShell 실행 스크립트와 작업 스케줄러 등록 안내.
- Windows용 Caddy 설정 및 NAS 리버스 프록시를 선택할 때의 적용 범위 안내. 실제 호스트/인증서는 아직 미확정이다.
- NAS/별도 저장소 백업: 로컬 백업 완료→임시 복사→체크섬→완료 폴더 전환, 동일 복사 재시도, 덮어쓰기 차단. NAS가 없거나 복사가 실패해도 로컬 백업 보존.
- 관리자 운영 점검 화면/명령: DB 연결, 미적용 마이그레이션, 원장 allocated/활성 예약 합계, 예정일 경과/미분류 확인. 데이터 자동 수정 없음. PG 공통 잠금 안에서 수량을 비교해 동시 거래에 의한 일시 불일치를 방지한다.
- 실제 비밀 파일/백업/로그/업무 스프레드시트를 Git에서 제외하는 규칙 추가.

### 검증

- SQLite 73개 발견: **70개 통과, PG 전용 3개 skip**.
- PostgreSQL 73개 발견: **71개 통과, SQLite 파일 전용 2개 skip**.
- 새 검증 9개: 정상/재시도 복사, NAS 연결 없음, 중단/손상 정리와 로컬 보존, 다른 백업 보호, Windows 실행 파일명, 예약 불일치 탐지/무수정, 관리자 권한, 미분류 예정 경고.
- 실제 PG dump를 로컬 디렉터리로 모사한 NAS에 복사하고 그 복사본을 새 PG DB로 복원해 전체 테이블/재고/예약/감사 내용 일치 확인. 실제 SMB NAS 테스트는 아니다.
- Waitress 기동·로그인 HTTP 응답 및 실제 Chromium 전체 업무 흐름/운영 점검 화면 통과. 가상 데이터 사용, JavaScript 오류 없음. 검증 OS는 Linux다.
- Windows Caddy 설정 validate 통과(Linux 실행 파일로 구문/구성 확인). 실제 Windows 경로/인증서/외부 접속 검증은 아니다.
- PowerShell 파일은 Windows PowerShell 5.1의 한글 인식을 위해 UTF-8 BOM으로 준비했다. 현재 PowerShell 실행 환경이 없어 실제 실행/파서 검증은 미실행이다. Windows CI는 추가했으나 push/원격 CI 실행은 하지 않았다.
- 기본 check, 마이그레이션 누락 확인, Git whitespace 확인 통과. 현재 빈 개발 DB의 읽기 전용 점검 통과.

### 다음 조건

회사 Windows 버전/RAM/디스크/계정 권한, DSM/RAM/Container Manager 및 NAS 공유 경로·실행 계정 권한 확인 후 실제 장비에 적용·검증한다. 현재 DS1621+ 정보만으로 설치된 Container Manager나 남은 메모리를 확정하지 않는다.

회사 장비를 사용하므로 이전 가격 조회용 네트워크 초안은 이 배포 경로의 필수 조건이 아니다. 환경 게시·서버 구매·공개 배포·NAS 관리 화면 접속·원격 push는 하지 않았다. 11/20 기능 목표와 11/30 전환·인수인계 목표는 유지한다.

## 배치 005 — ERP 대조·과거 이관·백업 복원·운영 준비

실행 기록: 한국 시간 2026-10-31 01:01~01:24, 약 23분 경과. 사용자 요청대로 독립 진행 가능한 작업을 이어갔으며 실제 서버/네트워크 적용이 필요한 지점에서 남은 조건을 분리했다. 경과시간을 최초 예상 인시와 동일하게 계산하지 않는다.

### 추가 구현

- 차이 원인·조치·미검토/원인 확인/조치 완료 기록과 감사 이력. 과거 비교 수량을 수정하지 않는다.
- Y02 수량과 자료 기준 시각을 부족표에 연결. 출하대기는 재고 화면에 품목 전체 참고값으로 표시하고 allocated와 이중 차감하지 않는다.
- 기존 입고/피킹·출고 BACKUP, 작업로그, AppSheet 과거 이동의 읽기 전용 보관 이관과 검색. 실제 거래를 재실행하지 않는다.
- 입고 원거래 전량 취소. 사유/취소 이력 보존, 가용량 부족 차단, 예정→도착 전환 후 원거래 취소 차단, 반복 POST 중복 차감 방지.
- SQLite 일관 백업, PostgreSQL pg_dump, SHA-256 manifest, 신규 파일/빈 DB 복원, 기존 데이터 덮어쓰기 차단.
- Gunicorn, Caddy/systemd/매일 백업 timer 초안, 운영 비밀값 없는 환경 예제, DEBUG=0 HTTPS/cookie 설정, 로그인 실패 제한, CI 설정.
- README, 사용/인수인계, 운영/복구, 검증/남은 조건 문서 정리. 개발계획 표를 최신 상태로 갱신했다.

### 외부 진행 조건

M1: 기반 구현, PostgreSQL 검증 대기. M2: 초기 이관·입고·조회 구현 및 SQLite/실데이터 대조 완료, 과거 이력/운영 검증 미완료. M3/M4: 서비스 기반만 구현. 전체 완료 단계는 여전히 0/7이며 미검증 영역을 완료로 계산하지 않는다.

다음은 PostgreSQL 실행/동시성 검증을 진행하고 피킹 코드·수량 붙여넣기 → 배정 결과/부족표 → 선택 Release 화면을 연결한다. 외부 서버 선정/구매는 별도 비용 검토 후 승인받는다.

## 마감 일정 갱신

## 배치 001 — 기반과 핵심 업무 규칙

상태: M1 진행 중. 전체 단계 완료 0/7. 환경 게시, 배포, 원격 push는 수행하지 않았다.

### 구현

- Django 5.2.18 프로젝트와 고정 의존성, 초기 DB 마이그레이션.
- 품목, 상태/위치별 재고, 프로젝트 예약, 이동 요청, 사용자 연계 감사 이벤트.
- 예정 재고 예약 허용, 가용량 초과 예약 차단.
- 원거래 예약 취소 및 재실행 차단.
- 선택 행 전량 Release, 미선택 예약 유지, 예정 상태 Release 차단, 실제 출고 시각과 확정 시각 분리.
- 모바일 이동 요청 처리 서비스: 가용량 검증, 완료/거부 기록, 재처리 중복 차감 방지.
- 로그인 필요 재고 검색 화면과 휴대폰에서 가로 스크롤 가능한 표.
- 업무 데이터의 관리자 직접 변경을 막아 서비스/감사 경로 우회 방지.

### 실행한 검증

- `manage.py migrate`: 새 개발 DB에 전체 마이그레이션 적용 성공.
- `manage.py check`: 문제 없음.
- `manage.py test`: SQLite에서 8개 테스트 실행·통과.
- 테스트 범위: 예정 재고 예약/Release 차단, 선택 출고와 중복 차단, 잘못된 혼합 배치 원복, 과다 예약 차단, 취소 수량 복구, 이동 예약 보호/재처리 방지, 잔량 부족 거부, 인증·검색 HTTP 응답.
- `manage.py makemigrations --check --dry-run`: 변경 누락 없음.
- 공개 서버나 운영 계정은 만들지 않았다. 자동 테스트용 계정은 테스트 DB 종료와 함께 제거됐다.

### 남은 일과 한계

- PostgreSQL 서버는 이 환경에서 발견되지 않았다. 드라이버와 설정은 있으나 PostgreSQL 연결/동시 처리 테스트 미실행.
- 입력 화면, Excel 이관, 입고 도착 전환, 피킹 배정 알고리즘, PDF, ERP 대조, 백업/복원 미구현.
- 실데이터/실물 대조, 브라우저 시각 검증, 배포 및 운영 검증 미실행.
- 핵심 서비스 코드는 시작점이며 웹에서 거래를 생성/확정할 수 있는 완성 앱이 아니다.
