## 배치 016 — 피킹 인쇄 밀도·사용자 설정

기록: 한국 시간 2026-10-31. 사용자가 실제 인쇄량이 많다고 알려 표 크기와 간격을 조정했고, 이어 요청한 사용자 설정과 ‘80% 인쇄가 적당’이라는 피드백까지 반영했다.

- 기본/고객 피킹 양식에 인쇄 설정 패널: 글자 7~12pt, 행 간격 좁게/보통, 기본값 복원. 화면/인쇄 표에 즉시 반영하며 브라우저별 저장/두 양식 공통 적용. 저장 차단/잘못된 저장 값에도 기본값으로 동작한다.
- 기본 8pt·좁은 간격. 기존 10pt의 80%를 기준으로 글자 크기를 맞췄다. 제목 12pt/셀 위아래 간격 축소/안내문 인쇄 제외. 브라우저 실제 배율은 강제 변경하지 않으며 새 기본값은 100%로 출력하도록 안내한다.
- ERP CODE 한 줄 맞춤은 선택 크기와 연동해 실제 글자 폭을 측정한다. 행/코드/수량을 삭제하거나 말줄임하지 않는다. 제목/인쇄 여백/열 폭은 양식 기준을 유지하며 표는 여러 페이지에 정상 출력한다.
- 실제 Chromium/PDF 동일 가상 96행 비교: 고객 양식 7→3페이지, 기본 양식 8→5페이지. 코드 96개가 각각 완전한 단어로 보존됨을 PDF 텍스트로 확인했다. 이는 가상 fixture의 결과이며 모든 자료의 감소율을 보장하지 않는다.
- 12pt·보통 선택/새로고침/다른 양식 간 유지, 초기화/잘못된 값/저장소 차단, 설정 패널 인쇄 제외, 큰 글자에서도 ERP CODE 전체 보존을 확인했다. JS 오류 없음. 첫 비교 시험의 강제 screen 미디어 잔류를 수정해 두 양식 모두 print 미디어로 재검증했다.
- 산출물 validation/compact-print의 전후 PDF/화면/result.json/controls-result.json. Django check/collectstatic/whitespace 확인 통과. 인쇄 서식과 브라우저 설정만 변경해 DB/업무 모델/전체 거래 테스트는 변경·반복하지 않았다.

실제 Windows 프린터 출력은 사용자 확인 대상이다. 진행률은 단계 수 기준 5/7 약 71% 유지.

## 배치 014 — 대체 출고(빌림)·생산 입고분 상환·ERP 연결

기록: 한국 시간 2026-10-31. 사용자의 후속 업무 설명에 따라 당초 ‘대체품 일반 Release’ 설계를 적용하지 않고 빌림/상환으로 분리했다. 고객은 대체품을 계속 사용하고 생산 입고분을 재고 코드 전환으로 갚는 방식이다.

### 구현

- 부족한 신규 피킹 요청에 명시적 대체 코드/위치/수량/사유를 배정. 고객 요청 코드와 실제 재고 코드를 별도로 보존한다. 전량 부족은 명시적 대체 배정용 주문을 만들 수 있다.
- 대체 출고는 전용 ‘빌림’ 처리. 실제 B 현재고/예약을 함께 차감하고 미상환으로 남긴다. 일반 Release 서비스/목록에서 분리해 일반 출고 확정을 차단한다. 출고 전 예약 취소는 감사 기록과 함께 가능하다.
- 생산 입고 A를 줄이는 만큼 B를 새 입고 위치에 늘리는 1:1 상환. 실제 재출고/추가 입고가 아니며 총수량은 유지한다. 부분 상환, 입고별 사용량, 가용량/범위/취소 상태/생산 입고 시점, 제품 동일성·필요 수정 완료 확인, 요청 재전송 방지, DB 잠금/감사 원복 적용.
- 예정 선등록→빌림 후 실제 도착도 입고 연결로 상환 가능하도록 Receipt.arrival_stock을 기록한다. 상환에 사용한 원입고는 취소를 차단한다. 전량 상환 후 회사 ERP 확인/확인 취소는 수량을 바꾸지 않고 이력으로 남긴다.
- 피킹 기본/고객 양식과 대체 기록에서 요청→실물→미상환→입고 건→코드/위치 전환 추적. 완료 출고 위치는 상환 위치로 덮어쓰지 않는다.
- ERP 대조/엑셀에 관련 건수와 기준시각 미상환을 연결. 후속 상환으로 과거 비교/미상환 수량을 덮어쓰거나 차이를 자동 해결하지 않는다. 현재 확인 상태와 과거 기준값을 구분한다.
- 운영 점검에 대체 상태/상환 합계 검증 추가. 0011_substitute_loans 마이그레이션으로 기존 재고/예약은 보존하고 새 테이블/선택 필드/상태를 추가한다.

### 검증

### 구현
